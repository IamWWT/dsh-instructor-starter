# Presentation craft（课件与 PPT 制作）

## 核心原则（源自开源社区共识：presenter / LearnDeck / lecture-slides / talksmith）

- **讲稿是真源（single source of truth）**：先写讲稿（大纲 → 逐页讲解词），PPT/视频都是讲稿的投影。讲稿以 Markdown/JSON 保存（如 `script/outline.md` → `script/speaker-notes.md`），幻灯片由讲稿生成或对齐，禁止画面与讲解脱节。
- **知识先于版式**：先整理内容（大纲/要点/证据），再谈美化；不要从空白 deck 开始堆模板。
- **一页一主题**：每页一个论点，信息密度适中；讲稿每页对应讲解词，标注时长（如 30s/90s）。

## 0. 开工产出确认（必做，不默认全做）

先问用户**这次要什么产出**，只做被点名的，不要全部覆盖：

| 产出 | 说明 |
|---|---|
| HTML 幻灯片 | 自包含网页 PPT（可全屏/可离线） |
| 视频 | 录屏 + 配音 + 字幕合成 mp4 |
| 课件/讲义 | Markdown 讲义或可打印课件 |
| 讲稿/口播稿 | 逐页讲解词（给演讲者本人用） |
| 问答预案 | 评委/学员追问预案 |
| 其它 | 用户自定义 |

- 一次性问清（ask_user_question，选项+推荐），用户没提的产出**不做**；中途说"顺便也要 X"再补。
- 产出目标先于内容组织：知道要 PPT 还是视频，才决定内容密度与呈现方式（PPT 逐页、视频按阶段）。

## 内容组织

1. 明确对象与时长：听众是谁（评委/学员/同行）、时长多少、核心目标（说服/教学/汇报）。
2. 结构：开场（背景+问题）→ 主体（方案/内容，分节）→ 收尾（总结+价值+下一步）。答辩额外加「边界与答疑」。
3. 讲稿分层：大纲（一页一行）→ 逐页讲解词（口语化，讲得出口）→ 备用 Q&A（可能的追问）。

## HTML 幻灯片规范（借鉴 veinmap 答辩实战教训）

- **全屏可操作**：提供可点击的全屏按钮（浏览器全屏 API），不能只是"按 F"；演示前实测。
- **文字可读**：正文 ≥ 24px 量级、标题更粗更大；不因塞内容把字号压到不可读。
- **版面组织**：图片与文字分区明确，不留大片空洞也不堆叠；按视觉重心排列。
- **引用可点击**：md/HTML 中引用的其他文档、图片、链接必须可跳转（相对路径正确），评委点击要能到达。
- **动画与内容一致**：演示动画内容不得多于 PPT 正文（动画只是强调，不是新增信息）。
- 自检：用截图/视觉工具（vision）检查每页渲染效果，字体、对齐、全屏按钮实测。

## 产物

- `script/outline.md`（大纲）
- `script/speaker-notes.md`（逐页讲解词，含时长）
- `slides/`（HTML 幻灯片，自包含、可离线打开）
- `script/qa-prep.md`（评委/学员追问预案，可选）
